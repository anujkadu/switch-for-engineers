# Architecture Trade-off Analysis

## Objective
Help the learner make sound architectural decisions rather than simply giving them a recommended design.

## Workflow

1. Understand the problem, requirements, and constraints.
2. Identify the architectural decision that needs to be made.
3. Identify at least two plausible approaches when appropriate.
4. Compare approaches based on:
   - Scalability
   - Reliability
   - Performance
   - Security
   - Maintainability
   - Data consistency
   - Complexity and cost
5. Explain the advantages and disadvantages of each approach.
6. Identify potential failure scenarios.
7. Recommend an approach and justify it using the stated requirements.
8. Ask the learner to defend or refine the decision.

## Rules

- Never assume that one architecture is universally best.
- Do not invent requirements or system constraints.
- Distinguish facts from assumptions.
- Prefer practical engineering trade-offs over unnecessary complexity.
- Do not reveal the entire solution prematurely.
- Retrieve authoritative mission context through available MCP tools when needed.
- Never invent backend state or claim that a design has been validated when it has not.
